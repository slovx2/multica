对话适合还没有形成明确任务的工作：梳理想法、查询工作区情况、讨论方案，或者先让智能体完成一个小任务。

**对话（Chat）是你和 [智能体](/agents) 的一对一独立沟通**——跳出 [任务](/issues) 看板。智能体默认**没有任何任务上下文**——它不盯着你的看板，也不会自己把对话变成任务——整段对话**完全私人**（[工作区](/workspaces) 里其他人、包括 admin 都看不到）。适合和智能体讨论方案、做 brainstorming、问一个不属于任何任务的问题。

新对话**默认没有 issue 上下文**：智能体不会自动收到任务的描述和评论，但仍可以在权限范围内用 Multica CLI 查询工作区、项目、任务和 skill。

点击输入框上方的**无项目**标签，可选择或更换[项目](/projects)。智能体会收到项目的描述、仓库和资源。从项目页进入聊天会自动选中该项目。本地目录资源的 `scope=chat` 只对聊天生效；默认的 `scope=all` 也对 issue 执行生效。

## 开始对话

1. 打开侧边栏中的**对话**。
2. 点击新建，选择一个你有权运行的智能体。
3. 输入消息，也可以附加图片或文件。
4. 发送后，Multica 会为这条消息创建一次执行，回复会回到当前对话。

运行时离线时，消息会等待它重新上线。智能体被归档，或者你失去调用权限后，不能继续发送新消息。

第一条消息发送前，对话页会显示所选智能体配置的最多三个建议。选择后会把完整提示词填入输入框而不会发送，方便你先调整。未配置建议的智能体会使用本地化的通用示例。

## 计划模式与规划对话

Claude Code 和 Codex 支持输入框上方的**计划模式**标签，状态保存在当前对话中。其他运行时会明确提示不支持。

智能体的原生提问会显示为卡片，支持选项和自由输入。提交回答后，会在同一个会话中开始下一轮。原生计划显示为 Markdown 卡片：

- **同意，创建/更新 issue**：自动关闭计划模式，要求智能体把计划写入 issue，不实施计划。
- **不同意**：将意见作为下一轮输入，继续在计划模式下修改。新计划会取代旧的待定计划。

等待决定时，当前智能体进程已经结束。界面不提供“批准并实施”的入口。

聊天中创建或更新的 issue 会自动关联该规划对话，两侧均可跳转。关联不会向其他成员开放私人聊天记录。在 issue 评论中明确 @ 同一个规划智能体时，会沿用最近关联的活跃对话、目录和模式处理，回复发在 issue 评论里，聊天中留下跟进记录。普通负责人评论唤醒保持原有行为。

也可以使用 CLI 手动关联或解除关联：

```bash
multica issue update ISSUE --planning-chat CHAT_SESSION_UUID
multica issue update ISSUE --planning-chat CHAT_SESSION_UUID --unlink-planning-chat
```

## 对话与任务的选择

| 需要 | 更适合 |
|---|---|
| 快速提问、探索方案或处理私人草稿 | **对话** |
| 明确负责人、状态、优先级和交付结果 | **任务** |
| 让团队成员查看背景并继续讨论 | **任务** |
| 临时查看工作区信息，不需要建立工作记录 | **对话** |

在 Multica 中创建的直接对话只对创建者开放，其他工作区成员和管理员不能读取。需要团队共同查看的结论，应整理到任务、项目说明或 skill 中。

## 多轮上下文

同一段对话会尽量继续 AI 编程工具中的原会话，因此后续消息不需要重复前面的内容。Multica 会保存会话标识，并把后续执行路由到能够访问该会话的运行时。

如果本地会话已经不存在、上下文无法继续，或者上一次错误不适合复用，运行时会从新会话开始。对话中的历史消息仍然保留。

## 查看和停止执行

智能体运行时，界面会显示当前阶段和工具活动。展开**查看详情**可以检查更完整的执行过程。

需要中断时，点击输入框旁的停止按钮。已经返回到对话中的内容会保留；尚未开始处理的输入会尽量恢复到编辑框中。

## 整理对话列表

对话支持重命名、置顶、归档和删除：

- **置顶**把常用对话固定在列表前面；
- **归档**把对话移到"已归档"并设为只读；
- **取消归档**后可以继续发送消息；
- **删除**会永久移除对话及其中的消息。

如果对话绑定了外部渠道（如 Slack），归档时绑定会断开，取消归档不会恢复，需要重新绑定。

<Callout type="warning">
删除对话无法撤销，并会停止其中尚未结束的执行。暂时不需要时用归档。
</Callout>
